# Sessão 2026-05-25 — status_do_fluxo: bug fix + dias_para_inicio

## Contexto
Tabela `status_do_fluxo` no warehouse `wh_siplan_rps` registra `id`, `autonomia` e `StatusGeral` (incluindo "Não enviadas") para controle do fluxo de autorização SiplanRPS. A tarefa era adicionar controle de quantos dias faltam para o início de cada atividade, de forma que o campo possa ser usado como slicer no modelo semântico do Power BI.

---

## Bug encontrado e corrigido

O notebook que gera `status_do_fluxo` lia `analise_siplan_rps` **do lakehouse** (`lake_gold_fatos`), quando deveria ler **do warehouse** (`wh_siplan_rps`), onde os usuários efetivamente alteram os status.

```python
# ERRADO — lia do staging sem edições dos usuários
df_ware = spark.sql("SELECT ... FROM lake_gold_fatos.dbo.analise_siplan_rps")

# CORRETO — lê do warehouse via JDBC
df_ware = (spark.read
    .format('jdbc')
    .option('url', jdbc_url)
    .option('dbtable', 'dbo.analise_siplan_rps')
    .option('accessToken', token)
    .option('driver', 'com.microsoft.sqlserver.jdbc.SQLServerDriver')
    .load()
    .select("atividade_id", "autonomia", "Status"))
```

## Campos novos adicionados à tabela

```python
from pyspark.sql import functions as F

dias = F.datediff(F.col("PrimeiraData"), F.current_date())

# No .select() do df_status:
df_filtrado["PrimeiraData"],
dias.alias("dias_para_inicio"),
```

```python
F.col("PrimeiraData").cast("date").alias("PrimeiraData")
```

## Como gravar no Fabric (lições aprendidas)

### O que NÃO funciona
| Abordagem | Problema |
|---|---|
| `spark.read.synapsesql()` | Não disponível neste ambiente |
| JDBC write → Warehouse | 16+ minutos, inviável |
| `save("abfss://...Tables/tabela")` | Grava arquivos mas não registra no catálogo → tabela aparece fora do `dbo`, sem dados no preview |
| `NVARCHAR(n)` em `createTableColumnTypes` | ParseException no Spark — usar `VARCHAR(n)` |
| tipo `datetime` via JDBC | Não suportado no Fabric Warehouse — usar `DATE` |
| Views T-SQL | Incompatíveis com Direct Lake |

### O que funciona
```python
# Ler do warehouse
df = spark.read.format('jdbc') \
    .option('url', 'jdbc:sqlserver://ENDPOINT;database=wh_siplan_rps;encrypt=true;trustServerCertificate=false') \
    .option('dbtable', 'dbo.tabela') \
    .option('accessToken', mssparkutils.credentials.getToken('https://database.windows.net/.default')) \
    .option('driver', 'com.microsoft.sqlserver.jdbc.SQLServerDriver') \
    .load()

# Gravar no lakehouse (registra no catálogo, aparece no dbo)
df.write.format("delta").mode("overwrite") \
    .option("overwriteSchema", "true") \
    .saveAsTable("lake_gold_fatos.dbo.status_do_fluxo")
```

Para o warehouse enxergar a tabela via SQL endpoint: criar **Shortcut** no `wh_siplan_rps` apontando para `lake_gold_fatos.dbo.status_do_fluxo`.

## Uso no modelo semântico
- `faixa_prazo` → slicer de lista categórico (prefixo numérico garante ordenação correta)
- `dias_para_inicio` → slicer de intervalo numérico (arrastar o máximo para 10, 20, 30, 45, 60)
- Atividades já ocorridas: `dias_para_inicio < 0` / `faixa_prazo = "0. Já ocorreu"`

## Notebook que gera a tabela
Não identificado localmente — existe no Fabric. Estrutura das células:

1. Imports + config JDBC
2. Lê `lake_gold_fatos.dbo.base` via `spark.sql()` — `atividade_id`, `autonomia`, `PrimeiraData` (cast date)
3. Lê `wh_siplan_rps.dbo.analise_siplan_rps` via JDBC — `atividade_id`, `autonomia`, `Status`
4. Filtra `year(PrimeiraData) >= year(current_date())`
5. Join left + computa `StatusGeral`, `dias_para_inicio`, `faixa_prazo`
6. Cache + verificação (`df_status.count()` deve ser ~38.000)
7. `saveAsTable("lake_gold_fatos.dbo.status_do_fluxo")`
